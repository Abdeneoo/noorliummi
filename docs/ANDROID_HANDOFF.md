# تسليم: تطبيق أندرويد لـ «نور لأمي» (Noor Li Ummi)

> انسخ هذا الملف كاملًا لـ Claude Code كأول رسالة في مشروع التطبيق.

## 1) ما هو المشروع
- منصة إسلامية مجانية غير ربحية، **صدقة جارية عن روح «أمل مجدي منير»** (والدة صاحب المشروع). يُذكر اسمها في شاشة «عن التطبيق» وشاشة الإهداء وصفحة المتجر بعبارة دعاء لها.
- الموقع الرسمي: https://noorliummi.io — بيئة الاختبار: https://staging.noorliummi.io
- الكود (عام، AGPL-3.0): https://github.com/Abdeneoo/noorliummi — اقرأ `CLAUDE.md` و`docs/DATA_SOURCES.md` و`docs/CONTENT_LICENSES.md` و`apps/extension` قبل أي شيء.
- للتواصل مع صاحب المشروع: https://www.facebook.com/3abdeneo

## 2) قواعد لا تُكسر
1. **نص القرآن لا يُعدَّل أبدًا** (Tanzil Uthmani، CC BY 3.0 — يُعرض كما هو مع ذكر المصدر).
2. لا نص ديني مولَّد بالذكاء الاصطناعي، ولا ترجمة آلية لمحتوى ديني، ولا فتوى آلية. كل محتوى ديني يأتي من مصدر موثق في `DATA_SOURCES` فقط.
3. **لا تتبع ولا تحليلات ولا إعلانات ولا جمع بيانات** (لا Firebase Analytics ولا Crashlytics ولا أي SDK إعلاني). نموذج Data safety في المتجر = «لا يجمع بيانات».
4. لا عدّادات أجر/ثواب. التسجيلات الصوتية للمستخدم (التسميع) تبقى خاصة ولا تُرفع إلا بموافقة صريحة لكل تسجيل.
5. لا أسرار في Git: ملف التوقيع (keystore) وكلماته خارج المستودع (GitHub Secrets أو جهاز المالك). لا تطلب كلمات مرور في المحادثة.
6. لا خدمات مدفوعة دون موافقة المالك (حساب Google Play Developer رسومه 25$ مرة واحدة — يفتحه المالك بنفسه).
7. المستودع عام: لا تكتب فيه IP السيرفر ولا أسماء مواقع المالك الأخرى ولا بيانات شخصية.
8. لا تلمس السيرفر ولا الإنتاج. التطبيق يقرأ فقط من الـ API العام؛ أي تغيير في الموقع يتم بـ PR على staging أولًا.

## 3) القرار التقني المقترح
**تطبيق أصلي Kotlin + Jetpack Compose**، minSdk 26، targetSdk أحدث مستوى يطلبه المتجر.
- مواقيت الصلاة تُحسب **على الجهاز بلا إنترنت** بمكتبة Adhan الرسمية لـ Kotlin/Java (`com.batoulapps.adhan:adhan2`، MIT) — نفس المحرك المستخدم في الموقع والإضافة (`packages/prayer-engine` يعتمد Adhan JS)، فتتطابق النتائج. اكتب اختبارات تطابق أوقات 3 مدن مع `/api/v1/times`.
- صفحات المحتوى الطويل (المصحف، الكتب، الحديث، الدروس) تُفتح من الموقع عبر **Custom Tabs** (أو WebView مقيد بنطاق noorliummi.io فقط) — لا تنسخ المحتوى داخل التطبيق في الإصدار الأول.
- التخزين محلي فقط: DataStore للإعدادات، Room للورد/التقدم.

## 4) الميزات (مطابقة لإضافة كروم v1.2.0 في `apps/extension`)
| الميزة | ملاحظات التنفيذ |
|---|---|
| مواقيت اليوم + عدّ تنازلي للصلاة القادمة + التاريخ الهجري | ويدجت للشاشة الرئيسية (Glance) |
| الأذان عند الوقت + تنبيه قبل الصلاة (دقائق يختارها المستخدم) | `AlarmManager.setExactAndAllowWhileIdle` + إذن `SCHEDULE_EXACT_ALARM` (يطلبه من المستخدم بشرح؛ لا تستخدم `USE_EXACT_ALARM`)، وإشعار بقناة صوت الأذان. أعد الجدولة بعد `BOOT_COMPLETED` وتغيير المنطقة الزمنية |
| أصوات الأذان | من `GET /api/v1/adhans` (كل صوت بترخيصه ومصدره). تُنزَّل عند اختيار المستخدم وتُخزَّن محليًا، وتُعرض صفحة الترخيص |
| القبلة | اتجاه من الإحداثيات (Adhan `Qibla`) + بوصلة الحساسات مع تنبيه المعايرة |
| الموقع | يدوي (قائمة مدن) أو موقع الجهاز `ACCESS_COARSE_LOCATION` عند الطلب فقط، لا يُرسل لأي خادم. اقتراح طريقة الحساب حسب الدولة (`nearestMethod` في `apps/extension/src/engine.ts`) |
| مذهب العصر | الجمهور/الحنفي |
| تذكير الضحى وقيام الليل (الثلث الأخير) | من المواقيت المحسوبة |
| تذكير الورد اليومي حتى يُنجَز | يتكرر بفاصل يختاره المستخدم ويتوقف عند «تم» |
| تذكير الأذكار والاستغفار والصلاة على النبي ﷺ | نصوص الأذكار من `GET /api/v1/adhkar?chapter=27|28|29` فقط (حصن المسلم) |
| صيام الاثنين والخميس والأيام البيض | تُستثنى الأيام المحرمة/غير المناسبة كما في `fastReason` (رمضان، 1 شوال، 10–13 ذو الحجة) |
| سورة الكهف يوم الجمعة | تذكير |
| وضع النوم | إيقاف التذكيرات غير الأذان في فترة يحددها المستخدم |
| آية وحديث اليوم | `GET /api/v1/ayah-of-day` و`/hadith-of-day` مع رابط المصدر |

## 5) الـ API العام (للقراءة فقط، بلا مفتاح)
القاعدة: `https://noorliummi.io/api/v1/` — CORS مفتوح، **حد 120 طلبًا/ساعة لكل IP** → خزّن النتائج يوميًا ولا تستعلم في حلقة.
- `ayah-of-day?date=YYYY-MM-DD`
- `hadith-of-day?date=YYYY-MM-DD`
- `adhkar?chapter=27` (صباح 27، مساء 28، نوم 29)
- `times?city=makkah&date=...` (للاختبار والمقارنة فقط؛ الحساب الفعلي على الجهاز)
- `adhans`
أي endpoint جديد يحتاجه التطبيق: PR على المستودع، يُختبر على staging، ولا يُنشر إلا بموافقة المالك.

## 6) الهوية والواجهة
- عربي أولًا مع RTL كامل، ثم الإنجليزية (والأردية والتركية والإندونيسية لاحقًا كما في الموقع).
- الألوان والخطوط من `docs/DESIGN_SYSTEM.md` و`docs/BRAND_GUIDELINES.pdf`، والأيقونة من `apps/web/public`.
- إمكانية الوصول: TalkBack، أحجام خط ديناميكية، تباين AA.

## 7) النشر
- اسم الحزمة المقترح: `io.noorliummi.app`.
- بناء AAB بـ GitHub Actions، والتوقيع من Secrets. نسخة داخلية (Internal testing) أولًا، والمالك يرفعها بنفسه من حسابه.
- صفحة سياسة الخصوصية: رابط لصفحة الخصوصية في الموقع (لا جمع بيانات).
- الترخيص AGPL-3.0 مثل المشروع، مع شاشة «المصادر والتراخيص» تنقل ما في `/sources`.

## 8) تعريف «تم»
اختبارات وحدة للمواقيت والجدولة والصيام، اختبار على جهاز حقيقي (أندرويد 14+ مع توفير البطارية)، تقرير صادق بما نجح وما لم ينجح، ولا شيء يُنشر في المتجر دون موافقة المالك.
