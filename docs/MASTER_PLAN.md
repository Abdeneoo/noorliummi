02. PROJECT VISION

أريد إنشاء منصة إسلامية رقمية عالمية ضخمة ومتكاملة باسم "نور لأمي"، تكون صدقة جارية عن روح والدتي رحمها الله.

الهدف هو بناء منظومة إسلامية رقمية متكاملة، وليس مجرد موقع إلكتروني لقراءة القرآن والأذكار.

أريد أن تصبح المنصة مرجعًا يوميًا للمسلمين حول العالم، ومصدرًا للعلم النافع، وأداة مجانية للأفراد والأسر والأطفال والمعلمين والمساجد والمراكز الإسلامية والمطورين.

أريد مستوى تصميم وتجربة استخدام وأداء يضاهي أفضل المنصات الرقمية العالمية.

لا أريد مشروعًا تجريبيًا أو واجهات شكلية أو موقعًا تقليديًا أو نسخة معدلة بصورة سطحية من قالب جاهز.

أريد مشروعًا حقيقيًا، متكاملًا، قابلًا للتوسع والاستمرار لعشرات السنوات.

- تجويد متقدم (اختياري، المرحلة 2): نموذج `Hisnlabs/tajweed-v2` — ‏23MB ONNX، يعمل على CPU، يميز المد والغنة والإخفاء والإدغام والقلقلة، لحفص وورش

## 2) الحفظ بخوارزمية FSRS بدل جدول مراجعة ثابت
**الفكرة:** بدل "راجع بعد يوم / 3 أيام / أسبوع" بشكل ثابت، كل آية تصبح بطاقة لها Stability و Difficulty و Retrievability، والخوارزمية تحسب موعد المراجعة الأمثل لكل مستخدم من تاريخ مراجعاته.

**المصادر:**
- `open-spaced-repetition/py-fsrs` — تنفيذ Python رسمي لـ FSRS، فيه `Scheduler, Card, Rating, ReviewLog, Optimizer`
  - https://github.com/open-spaced-repetition/py-fsrs
- `open-spaced-repetition/fsrs-rs` — تنفيذ Rust مع Bindings لـ Python و Node.js و Dart و PHP
  - https://github.com/open-spaced-repetition/fsrs-rs
- الخوارزمية نفسها المستخدمة في Anki الحديث، وتتفوق على SM-2 القديم.

**تعليمات لكلود:**
- استخدم `fsrs` في `packages/islamic-core` أو خدمة الحفظ، وخزّن لكل آية: `stability, difficulty, due_date, review_history`.
- اربطها بخطة الحفظ والختمة الموجودة في الخطة، ولا تستبدل واجهة الحفظ الحالية، فقط غيّر محرك الجدولة تحتها.

## 3) قرآن كلمة بكلمة + إعراب وصرف — من مصدر أكاديمي
**الفكرة:** عند الضغط على أي كلمة في المصحف تظهر: معناها، نوعها (اسم/فعل/حرف)، إعرابها، وجذرها. هذا يحوّل القراءة إلى تعلّم للغة القرآن، ولا يوجد في معظم المنصات العربية بهذا العمق.

**المصدر:**
- **Quranic Arabic Corpus** — جامعة Leeds، تغطية 77,429 كلمة في القرآن، مع POS tagging وتقطيع صرفي وشجرة إعراب Dependency Graph
  - صفحة التنزيل: http://corpus.quran.com/download/
  - الموقع: https://corpus.quran.com/
  - الترخيص: **GNU GPL، للاستخدام غير التجاري فقط، مع ذكر المصدر، وعدم تعديل ملف البيانات الأصلي** — يجب احترام هذا الشرط حرفياً.

**تعليمات لكلود:**
- استورد ملف v0.4 كما هو في جدول staging، ولا تعدّل النص القرآني، وافصل بيانات الإعراب عن نص Tanzil.
- اعرض الإعراب كطبقة اختيارية (Toggle) فوق النص، وليس افتراضياً، حتى لا تشتت القارئ.

## 4) تظليل كلمة بكلمة أثناء التلاوة — بتوقيت حقيقي ومرخّص
**الفكرة:** أثناء تشغيل التلاوة يتحرك التظليل كلمة كلمة، لا آية آية فقط. هذا كان ناقصاً في قسم الصوت في الخطة.

**المصادر:**
- **Quran Foundation API v4** — `chapter_recitations/{id}/{n}?segments=true` يعطي `timestamps` و `segments` على مستوى الكلمة
  - https://api-docs.quran.com/docs/sdk/javascript/audio/
- **cpfair/quran-align** — توقيت كلمة بكلمة لـ 12 قارئاً من EveryAyah (عبدالباسط، السديس، الحصري، المنشاوي...)، بيانات **CC-BY-4.0**، الكود MIT
  - https://github.com/cpfair/quran-align
- **QuranLab — quran-audio** على Hugging Face — توقيت CC-BY-4.0 لـ 44 تسجيلاً، و taxonomy موحد لـ 245 قارئاً، **ولا يستضيف ملفات صوتية**، فقط روابط للمصدر الأصلي
  - https://huggingface.co/datasets/quranlab/quran-audio

**تحذير مهم لكلود:**
- لا تجمع ملفات صوتية للقراء المشاهير داخل المستودع. البث (Streaming) فقط من المصدر، مع Attribution. التوقيت هو المرخّص بوضوح، الصوت نفسه حقوقه غير واضحة في معظم المصادر.

## 5) حديث جاهز للتشغيل فوراً بدون مفتاح API — بديل sunnah.com
**الفكرة:** مكتبة الحديث في الخطة تعتمد على sunnah.com، لكن API الخاص به يحتاج مفتاحاً يُطلب يدوياً، وموقعه يرد 403 على كثير من الطلبات الآلية. البديل الجاهز:

**المصدر:**
- **fawazahmed0/hadith-api** — الكتب الستة + الموطأ + الأربعون النووية وغيرها، عربي وإنجليزي وأردو وتركي وإندونيسي وبنغالي وفرنسي وروسي، **Unlicense (ملك عام)، بدون مفتاح، عبر CDN**
  - https://github.com/fawazahmed0/hadith-api
  - مثال: `https://cdn.jsdelivr.net/gh/fawazahmed0/hadith-api@1/editions/eng-bukhari/1/1.json`
  - فهرس كل النسخ: `https://cdn.jsdelivr.net/gh/fawazahmed0/hadith-api@1/editions.json`
- مكمل له: **fawazahmed0/quran-api** — أكثر من 90 لغة و 400 نسخة ترجمة، Unlicense، عبر jsDelivr أيضاً
  - https://github.com/fawazahmed0/quran-api

**تعليمات لكلود:**
- حمّل نسخة محلية من `editions.json` في `services/data-import`، وخزّنها في Postgres، ولا تعتمد على CDN وقت التشغيل إلا كـ Fallback.
- احتفظ برقم الحديث حسب المصدر + درجة الحديث حيث تتوفر، ولا تصنّف الأحاديث بالذكاء الاصطناعي.

## 7) دليل مساجد عالمي بدون Google Maps مدفوع
**الفكرة:** دليل المساجد في الخطة يحتاج قاعدة بيانات تُبنى من الصفر. البديل: OpenStreetMap فيه 337,994 مسجداً موثّقاً، مجاناً.

**المصدر:**
- **OpenStreetMap — Overpass API** — استعلام: `amenity=place_of_worship` + `religion=muslim` (+ `building=mosque`)
  - https://wiki.openstreetmap.org/wiki/Tag:building%3Dmosque
  - مثال الاستعلام في Overpass QL:
    ```
    node["amenity"="place_of_worship"]["religion"="muslim"](around:5000, LAT, LON);
    out;
    ```
  - الترخيص: **ODbL**، بدون مفتاح API، مع User-Agent مخصص.
- مرجع تنفيذ في Flutter يستخدم نفس الفكرة: `kmkholm/masjid-silencer`
  - https://github.com/kmkholm/masjid-silencer

**تعليمات لكلود:**
- لا تستعلم من Overpass في كل زيارة. خزّن نتائج المدن الكبرى في Postgres، وحدّثها أسبوعياً بـ Background Job، واسمح للمستخدم باقتراح تعديل (اسم، مواقيت إقامة، رقم تواصل) يُراجع قبل النشر.
- أضف ميزة فرعية قوية: **كتم الهاتف تلقائياً عند دخول المسجد** (Geofence من نفس بيانات OSM) — في تطبيق الهاتف فقط، وبموافقة المستخدم.

## 8) حاسبة زكاة بأسعار ذهب وفضة لحظية — مجاناً
**الفكرة:** حاسبة الزكاة في الخطة تطلب إدخال سعر الذهب يدوياً. أضف سعراً لحظياً مع تاريخ التحديث، وإدخالاً يدوياً كبديل.

**المصدر:**
- **api.metals.live** — `GET https://api.metals.live/v1/spot` يعطي ذهب وفضة وبلاتين وبلاديوم بالدولار للأونصة، **بدون مفتاح**
  - https://api.metals.live/v1/spot
- بديل احتياطي: سعر يدوي + خيار "استخدم سعر الأمس" مع إظهار التاريخ والوقت والمصدر بجانب النتيجة.

**تعليمات لكلود:**
- خزّن السعر في Redis لمدة ساعة، ولا تستعلم في كل حساب زكاة. اعرض دائماً: السعر، العملة، التاريخ، والنصاب بالغرام (85غ ذهب / 595غ فضة)، وشرح الحساب خطوة بخطوة.

## 10) ترجمة تطوعية منظمة — بدون Crowdin مدفوع
**الفكرة:** الخطة تريد 15 لغة. الترجمة العشوائية في ملفات ستفشل. نحتاج منصة ترجمة على نفس VPS.

**المصدر:**
- **Weblate** — منصة ترجمة مفتوحة المصدر، **GPL-3.0**، تتكامل مع Git مباشرة، وتدعم SSO و RBAC ومراجعة الترجمات
  - https://github.com/WeblateOrg/weblate
  - الموقع: https://weblate.org
  - التشغيل: Docker Compose (Weblate + Postgres + Valkey/Celery)، يحتاج 3GB RAM و 2 CPU كحد أدنى.

**تعليمات لكلود:**
- شغّل Weblate على Subdomain مستقل `translate.noorliummi.io`، واربطه بمستودع المشروع فقط لملفات واجهة المستخدم (JSON).
- **لا تترجم نص القرآن أو الحديث أو الأذكار عبر المتطوعين.** الترجمات الدينية تأتي فقط من المصادر الموثقة في القسم 42 من الخطة. Weblate لواجهة الموقع والدروس فقط.

## 11) تعديلات مهمة على الخطة الحالية — أعطها لكلود مع الأفكار

1. **لا تنسخ كود GPL مباشرة:** مشاريع `cloud-adhan` و `Noor-connect` وغيرها مرخّصة GPL-3.0. ادرسها كمرجع فقط، ولا تدمج كودها في مشروع مغلق أو بترخيص مختلف دون دراسة قانونية.
2. **لا تعتمد على sunnah.com كـ API أساسي:** استخدم fawazahmed0 (القسم 5 أعلاه) كأساس، وsunnah.com كمرجع روابط فقط.
3. **لا تفترض إذن تنزيل الصوتيات:** وجود MP3 على الإنترنت لا يعني إذن إعادة التوزيع. Streaming + Attribution فقط.
4. **حدّد MVP للإطلاق الأول:** قرآن + تفسير + تلاوة + مواقيت وأذان + أذكار + صفحات أثر. باقي الأقسام (أكاديمية، API عام، تطبيقات) مراحل لاحقة، ولا تؤخر الإطلاق بسببها.
5. **أضف التاريخ الهجري بدون API خارجي:** في المتصفح استخدم `Intl.DateTimeFormat('ar-SA-u-ca-islamic-umalqura')` المدمج في JavaScript، وفي الباكند استخدم Adhan JS الموجود أصلاً في الخطة للتقويم والقبلة والصلاة.
6. **أضف وضع "المسجد" للهاتف:** كتم تلقائي عند دخول المسجد (القسم 7)، وشاشة عرض مواقيت (موجودة في الخطة) — اربطهما بنفس بيانات OSM.
